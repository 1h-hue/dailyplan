功能与代码地图

静态网页：浏览器直接跑 HTML/CSS/JS，数据在 Supabase，发布在 Netlify。 没有 React/Vue，也没有单独的后端文件夹——业务几乎都在根目录几个文件里。

前端三件套 Supabase 云库 Netlify 发布

四个最关键文件（先记住这个）

日常改产品几乎只碰这四个。不要把「样子」和「内容」搞混，也不要把 schema.sql 当成存数据的地方。

文件 一句话 负责什么 不负责什么
index.html 页面骨架 + 有什么内容 标题、按钮、表单、两个标签页、列表等结构；决定页面上「有哪些东西」 不管颜色好不好看；也不直接读写云端数据
styles.css 长什么样 颜色、间距、字体、粉蓝配色、卡片布局、手机适配；按钮和模块的样式 不是页面内容本身；不写登录、添加任务等逻辑
app.js 点了之后干什么 登录、增删改计划、留言、睡眠记录、日期切换、实时同步；按下按钮后的一系列反应 不决定货架长什么样（表结构在 SQL）；也不单独画整页布局
supabase/schema.sql 数据库货架怎么设计 建表（plans / messages / sleep_records）、字段、权限（RLS）、触发器、Realtime 本身不存每天的计划数据；真正存数据的是 Supabase 云库。改完要在 SQL Editor 里 Run

记忆口诀：html = 有什么；css = 长什么样；js = 点了干什么；schema.sql = 仓库货架怎么搭。 另：不要双击打开 index.html，请用 py -m http.server 8080 再访问 http://localhost:8080，否则脚本可能不运行，页面只剩标题。

目录结构（该改哪）

真正要改产品的，几乎只有根目录三个文件 + supabase/schema.sql。其余是配置与文档。

文件 / 目录 职责 什么时候改它
index.html 页面骨架：登录区、两个标签页、列表和表单的 DOM 改文案、按钮、加一块新 UI 的外壳
styles.css 粉蓝配色、布局、卡片、列表、睡眠页样式 改颜色、间距、手机适配、动画
app.js 全部交互：读写 Supabase、渲染列表、标签切换、实时订阅 改业务逻辑、校验、数据怎么显示
config.js 本地 URL + anon key（不进 Git） 只改密钥；不要 commit
config.example.js 给协作者复制用的空模板 很少改
supabase/schema.sql 表结构、RLS、触发器、Realtime 发布 加表/改权限后在此写 SQL，再在控制台 Run
scripts/generate-config.mjs Netlify 构建时生成 config.js 部署配置出问题才动
netlify.toml 构建命令与发布目录 改部署方式时动
README.md 使用与协作说明 流程变了就更新文档

数据怎么分层

浏览器

index.html 画界面； styles.css 定样子； app.js 调 Supabase、更新列表。

Supabase

三张业务表：plans · messages · sleep_records。 Auth 管登录；RLS 管权限；Realtime 管同步。

Netlify

托管静态文件；构建时用环境变量生成 config.js。不存业务数据。

app.js 内部怎么找

单文件，按函数名搜即可，不必找「文件夹」。

计划

loadPlans / renderList / toggleDone / toggleShared / removePlan

留言

loadMessages / renderMessages / submitMessage / setMessageContext

睡眠

loadSleepRecords / recordSleepTime / renderSleepPerson / sleepDuration

壳子

boot / showLogin / showPlanner / switchTab / subscribe

改完怎么上线

本地 py -m http.server 8080 测过 → git commit → git push → 等 Netlify Published。 若改了 schema.sql，还要在 Supabase SQL Editor 再 Run 一次， 否则只有代码、没有新表。
